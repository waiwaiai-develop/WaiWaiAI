## 結論: 工数は本当に半分になった

WaiWai AIでは、2025年後半からClaude Codeを開発の中核ツールとして導入しました。その結果、**受託開発案件の平均工数が約50%削減**されました。

これは単にコードを生成させているだけではありません。プロジェクト設計、コードレビュー、テスト作成、ドキュメント生成まで、開発プロセス全体にAIを組み込んだ結果です。

## CLAUDE.mdが全てを決める

Claude Codeの威力を最大化するのが、プロジェクトルートに置く`CLAUDE.md`ファイルです。これはAIに対する「プロジェクトの脳」であり、ここに書いた内容がClaude Codeの行動を決定します。

### 良いCLAUDE.mdの構成

```markdown
# プロジェクト名

## 技術スタック
- フレームワーク: Next.js 15 (App Router)
- 言語: TypeScript (strict mode)
- スタイリング: Tailwind CSS 4

## コーディング規約
- 関数コンポーネントのみ使用
- 型定義は必ずinterfaceで（typeは使わない）
- エラーハンドリングはtry-catchで統一

## ディレクトリ構造
src/
  app/        # ルーティング
  components/ # UIコンポーネント
  lib/        # ユーティリティ
  data/       # データ定義

## やってはいけないこと
- any型の使用
- console.logのコミット
- .envファイルの変更
```

**ポイント**: 「やってはいけないこと」を明確に書くことで、AIの暴走を防ぎます。

## 開発フロー: AIとの協業パターン

### パターン1: 設計→実装の分離

```
Step 1: 要件を自然言語で伝える
Step 2: Claude Codeに設計案を出させる
Step 3: 設計をレビュー・修正
Step 4: 実装を依頼
Step 5: コードレビュー（人間 + AI）
```

重要なのは**Step 2と3を飛ばさないこと**。いきなり「実装して」と言うと、的外れなコードが生成されがちです。

### パターン2: テスト駆動AI開発

```
Step 1: テストケースを人間が設計
Step 2: テストコードをClaude Codeに書かせる
Step 3: テストが通る実装をClaude Codeに依頼
Step 4: エッジケースを追加
```

テストを先に書くことで、AIの出力品質が飛躍的に向上します。「何が正しいか」が明確に定義されているため、AIが迷走しません。

## 注意点: AIに任せてはいけないこと

万能に見えるClaude Codeですが、以下は人間が判断すべきです：

1. **アーキテクチャの最終決定** — AIは選択肢を出すが、決めるのは人間
2. **セキュリティ設計** — 認証・認可のロジックは必ず人間がレビュー
3. **ビジネスロジックの妥当性** — 技術的に正しくても、業務的に正しいかは別
4. **パフォーマンスのボトルネック** — AIは動くコードを書くが、最適なコードとは限らない
