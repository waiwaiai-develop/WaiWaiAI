## 結論: 工数55%削減

コード生成だけでなく、設計→実装→テスト→ドキュメントの全工程にClaude Codeを組み込んだ結果。

| 工程 | 従来 | Claude Code | 削減率 |
|------|------|-------------|--------|
| 初期設計 | 16h | 8h | 50% |
| フロント実装 | 40h | 16h | 60% |
| バックエンド実装 | 32h | 20h | 38% |
| テスト作成 | 16h | 4h | **75%** |
| ドキュメント | 8h | 2h | **75%** |
| コードレビュー | 8h | 4h | 50% |
| **合計** | **120h** | **54h** | **55%** |

## CLAUDE.mdが全てを決める

プロジェクトルートに置く設定ファイル。これがAIの行動品質を決定する。

```markdown
# プロジェクト名

## 技術スタック
- Next.js 15 (App Router) / TypeScript (strict)

## コーディング規約
- 関数コンポーネントのみ
- 型定義はinterfaceで統一

## やってはいけないこと
- any型の使用
- console.logのコミット
- .envファイルの変更
```

**「やってはいけないこと」を明確に書く**のが最重要ポイント。

## 効果が大きい2つのパターン

### パターン1: 設計→実装の分離

いきなり「実装して」ではなく、必ず設計フェーズを挟む。

```
要件伝達 → 設計案を出させる → レビュー・修正 → 実装依頼 → コードレビュー
```

### パターン2: テスト駆動AI開発

テストを先に書かせてから、テストが通る実装を依頼。「正解」が定義されているのでAIが迷走しない。

## AIに任せてはいけないこと

- **アーキテクチャの最終決定** — 選択肢を出すのはAI、決めるのは人間
- **セキュリティ設計** — 認証・認可は必ず人間がレビュー
- **ビジネスロジックの妥当性** — 技術的に正しくても業務的に正しいかは別
