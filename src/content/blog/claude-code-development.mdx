## やってみた率直な感想

当社ではClaude Codeを開発の主力ツールとして使っています。体感としては、特にテスト作成・ドキュメント・定型的な実装で大幅に楽になりました。一方で、設計判断やセキュリティ周りは依然として人間の仕事です。

## CLAUDE.mdが品質を左右する

プロジェクトルートに置く設定ファイル。ここにプロジェクトのルールを書くことで、AIの出力品質が大きく変わります。

```markdown
# プロジェクト名

## 技術スタック
- Next.js 15 (App Router) / TypeScript (strict)

## コーディング規約
- 関数コンポーネントのみ
- 型定義はinterfaceで統一

## やってはいけないこと
- any型の使用
- console.logのコミット
- .envファイルの変更
```

**「やってはいけないこと」を明確に書く**のが最重要。これがないとAIが暴走しがち。

## 効果を感じる使い方

### 設計→実装を分ける

いきなり「実装して」ではなく、設計フェーズを挟むと精度が上がる。

```
要件伝達 → 設計案を出させる → レビュー → 実装依頼 → コードレビュー
```

### テストを先に書かせる

テストケースを先に定義してから実装させると、「正解」が明確なのでAIが迷走しにくい。

## 特に効果が大きい領域

- **テスト作成** — 定型的で量が多い作業はAI向き
- **ドキュメント生成** — READMEやAPI仕様書など
- **定型的なCRUD実装** — パターンが決まっているもの

## AIに任せるべきでないこと

- **アーキテクチャの最終決定** — 選択肢を出すのはAI、決めるのは人間
- **セキュリティ設計** — 認証・認可は必ず人間がレビュー
- **ビジネスロジックの妥当性** — 技術的に正しくても業務的に正しいかは別

## まとめ

Claude Codeは万能ではないが、使いどころを見極めれば確実に開発速度は上がる。CLAUDE.mdの設計と、人間がレビューする体制を整えることが前提。
