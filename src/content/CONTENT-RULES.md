# ブログ記事コンテンツルール

## 1. 絶対ルール（違反厳禁）
1. **嘘を書かない** — 達成していない実績を「達成した」と書かない
2. **架空のデータを載せない** — 具体的な数字は実際のもののみ使用
3. **「〜できます」「〜が可能です」の表現を使う** — 「〜しました」は実績のあるもののみ
4. **月商や売上の具体額は非公開** — 倍率や傾向で表現
5. **エージェントの固有名詞は非公開** — 「総合窓口」「開発担当」等の役割名で記載
6. **倫理的にグレーな手法は書かない** — スクレイピング→「データ連携」「API連携」「自動取得」で表現
7. **クライアント名・案件の詳細は出さない** — 「不動産系企業」「飲食チェーン」等の抽象表現

## 2. トーン・文体
- **非エンジニアが読んでもわかる平易な日本語**で書く
- 専門用語は使わず言い換える（RAG→「自社データと連携したAI」、API→「システム間の連携」等）
- 正直で率直。できないこと・課題も書く → 信頼につながる
- 売り込み臭くしない。有益な情報 → 自然にサービスへ繋げる
- 「です・ます」調で統一。フランクすぎず、堅すぎず
- 一人称は「当社」。「弊社」は使わない（堅すぎる）

## 3. 読みやすさ（モバイルファースト）
- **1段落は最大3文**。4文以上の段落は分割する
- 見出し（h2）の間隔は画面スクロール2〜3回分を目安に
- 箇条書き・表・コードブロックを積極的に使い、テキストの壁を作らない
- 太字は1段落に1箇所まで。多用すると効果が消える
- 冒頭で結論を言う（逆ピラミッド構成）。最後まで読まなくても要点がわかるように

## 4. 記事構成（心理学ベース）

### 基本フロー: 課題共感 → 解決策 → 信頼 → 行動
1. **課題への共感**（冒頭） — 読者の「あるある」から始める。「○○でお困りではないですか？」ではなく、課題を事実として述べる
2. **解決の方向性** — 「こうすれば解決できる」を具体的に。テーブルやステップで視覚化
3. **信頼の根拠** — 当社の実際の取り組みに触れる（嘘のない範囲で）。使っているツール名・技術名は具体的に出してOK
4. **中間CTA**（記事の40〜60%地点） — blockquoteで自然に「ご相談承ります」。押し売りにならないトーンで
5. **ハードルを下げる末尾CTA** — 具体的な次のアクションを提示する

### CTA設計のポイント
- 「お問い合わせください」は抽象的でNG → 「30分の無料オンライン相談」のように具体化
- 「初回無料」「まずは○○から始められます」で心理的ハードルを下げる
- PaymentLinkButtonは記事末尾に1つ。記事の内容と関連する商品を配置
- 最終行は問い合わせページへの誘導テキスト

## 5. SEO

### タイトル・メタ
- titleに狙うキーワードを含める（前半に置く）
- title は35文字以内を目標（Google検索結果で切れないように）
- descriptionは80〜120文字。要点 + 行動喚起を含める
- slugは英語・ハイフン区切り・キーワード入り（例: `ai-restaurant-dx`）

### 見出し構成
- h2は3〜5個。多すぎると散漫になる
- h3は各h2に0〜2個
- 見出しにもキーワードを自然に含める

### 内部リンク
- 関連する自社ブログ記事があればリンクする
- サービスページ（/services）やお問い合わせ（/#contact）への導線を含める
- 商品ページ（/products）の関連商品にも触れる

### 記事の鮮度
- dateは作成日を正確に記載
- 古い記事は内容が陳腐化したら更新する（dateも更新）

## 6. WaiWai AIの強み（記事内で自然に使える差別化要素）
- AI活用を前提とした開発で通常より短い納期
- 代表自身がエンジニアなので、技術と経営の両面から提案できる
- 月1回のAI顧問プランなど、小さく始められるメニューがある
- 実際にAIを使って自社運営しているので、机上の空論ではない

## 7. NG表現
- 「革命的」「画期的」「最先端」「圧倒的」等の大げさな修飾語
- 「たった○○で」「驚きの」「信じられない」等の煽り表現
- 未達成の成果を断言する表現
- 他社を貶める比較
- 「〜すべき」「〜しなければならない」等の押し付け表現
- 「お客様の声」の捏造
